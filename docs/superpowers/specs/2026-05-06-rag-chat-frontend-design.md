# RAG 问答链路前端设计

## 背景

DevBrain-CQUPT 已有知识库、文档、分块、向量存储、Prompt、会话记忆等后端基础能力，但本阶段不新增后端 Controller。前端先实现 RAG 问答链路页面和服务层契约，后续后端按契约补齐接口后即可联调。

## 范围

本次只修改 `frontend` 侧页面、类型和 API 服务层。

- 前台 `/assistant` 使用「聊天主导」布局，面向普通使用者。
- 后台 `/admin/qa` 使用「链路调试台」布局，面向管理员或研发排查人员。
- 新增 `frontend/src/services/rag.ts`，封装约定接口。
- 新增 TypeScript 类型，描述会话、消息、引用、检索命中、Prompt 预览和调试运行结果。
- 页面必须覆盖加载态、错误态、空态和接口未就绪时的反馈。

不在本次范围：

- 不新增或修改后端 RAG Controller。
- 不实现流式 SSE / WebSocket。
- 不做真实 Prompt 模板编辑器。
- 不在前端存储 JWT。

## 约定接口

所有接口沿用现有 Axios 实例和统一响应包装解析。

| 场景 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 会话列表 | GET | `/rag/conversations` | 获取当前用户的 RAG 会话摘要 |
| 会话详情 | GET | `/rag/conversations/{conversationId}` | 获取指定会话消息 |
| 前台问答 | POST | `/rag/chat` | 发送问题，返回回答、引用和本轮链路摘要 |
| 后台调试 | POST | `/rag/debug/runs` | 执行一次调试问答，返回检索、Prompt 和回答详情 |

前端字段采用 camelCase。后端字段如需调整，只在 `services/rag.ts` 做适配，不让页面直接拼接请求。

## 前台 `/assistant`

前台沿用现有 AppShell 与侧边栏入口，替换当前静态内容。

页面结构：

- 左侧会话栏：新建会话、会话列表、会话加载失败和暂无会话空态。
- 中间聊天区：消息流、用户问题、助手回答、发送框、发送中状态和失败重试。
- 右侧辅助栏：知识库选择、Top-K 设置、本轮引用来源、检索命中和 Prompt 摘要。

交互规则：

- 页面加载时并行请求会话列表和知识库列表。
- 首次进入且没有会话时，展示空线程和推荐问题。
- 发送问题前校验非空问题；发送时禁用按钮并保留输入框内容。
- `/rag/chat` 成功后追加用户消息和助手消息，并刷新右侧本轮链路信息。
- `/rag/chat` 失败时保留用户输入，在线程底部显示错误卡片，提供重试按钮。
- 接口尚未接通时，页面展示真实错误信息，不伪造成功回答。

## 后台 `/admin/qa`

后台替换当前 `/admin/qa` 占位页，使用链路调试台布局。

页面结构：

- 顶部调试表单：问题、知识库选择、Top-K、是否返回 Prompt、执行按钮。
- 链路概览：检索、Prompt、Chat 三段状态和耗时字段。
- 检索结果面板：展示每个命中 Chunk 的分数、知识库、文档、索引和内容片段。
- Prompt 面板：展示 baseTemplate、kbContext、mcpContext、question 和最终 prompt 预览。
- 回答面板：展示 answer、引用、错误信息和空态。

交互规则：

- 页面加载时请求知识库列表，失败时仍允许输入问题，但知识库选择显示错误提示。
- 执行调试时调用 `/rag/debug/runs`。
- 调试请求成功后，三个面板同时更新。
- 调试请求失败时，保留上一次结果，并在顶部显示错误条。
- 没有执行过调试时，各面板展示空态。

## 状态与错误处理

- 加载态：列表、发送、调试运行分别独立控制，不互相阻塞。
- 空态：没有会话、没有消息、没有引用、没有检索命中、没有 Prompt 时分别给出短提示。
- 错误态：直接展示 `Error.message`，并提供重试入口。
- 权限失效：继续依赖现有 Axios 401 事件和认证守卫。
- 写请求：继续由现有 Axios 拦截器自动附加 `X-XSRF-TOKEN`。

## 视觉方向

保持项目已有的工作台风格：低饱和背景、8 px 左右圆角、清晰表格和紧凑信息密度。前台更轻，突出聊天主线；后台更密，突出检索、Prompt、Chat 的可观测性。新增样式集中放在 `styles.css`，命名以 `rag-`、`qa-` 或现有上下文类为前缀，避免影响知识库和流水线页面。
