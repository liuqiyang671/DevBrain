**4. 每个文件的修改目的**

`KnowledgeBaseDO`：承接数据库字段。

`KnowledgeBaseMapper`：提供基础 CRUD、分页查询、唯一性查询能力。

`KnowledgeBaseServiceImpl`：核心业务规则放这里，包括：

- `collectionName` 格式校验：字母开头，只含字母、数字、下划线、中划线。
- `collectionName` 唯一校验。
- `name` 长度 1-128，`description` 最大 512。
- 创建 / 更新写入 `createdBy`、`updatedBy`。
- 更新时禁止修改 `collectionName`。
- 删除使用 MyBatis-Plus 逻辑删除。
- 分页默认过滤 `deleted = 0`，按 `updateTime` 倒序。

`KnowledgeBaseController`：提供 REST 风格接口：

- `POST /knowledge-base`
- `GET /knowledge-base`
- `GET /knowledge-base/{id}`
- `PUT /knowledge-base/{id}`
- `DELETE /knowledge-base/{id}`

`schema.sql`：新增表结构，并补充：

- `knowledge:read`
- `knowledge:write`
- `GET /knowledge-base/**`
- `POST /knowledge-base/**`
- `PUT /knowledge-base/**`
- `DELETE /knowledge-base/**`

数据库表结构如下
```sql
CREATE TABLE t_knowledge_base (
    id VARCHAR(20) PRIMARY KEY,
    name VARCHAR(128) NOT NULL,
    embedding_model VARCHAR(64) NOT NULL,
    collection_name VARCHAR(64) NOT NULL,
    created_by VARCHAR(20) NOT NULL,
    description VARCHAR(512),
    workspace_id VARCHAR(20),
    updated_by VARCHAR(20),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    deleted SMALLINT DEFAULT 0,
    CONSTRAINT uk_collection_name UNIQUE (collection_name, deleted)
);
CREATE INDEX idx_kb_name ON t_knowledge_base(name);
```
**5. 准备采用的实现方案**

采用“参考 Ragent 业务结构，用famework中的基础组件”的方案：

- 包结构按目标项目新增 `edu.cqupt.devbrain.knowledge`。
- DTO/VO 优先参考目标项目用户模块，使用 `record` 或简单 Java 类，不新建基础响应/分页/异常类。
- Controller 只做参数接收和 `Results.success(...)` 包装。
- Service 用 MyBatis-Plus `Wrappers.lambdaQuery` 完成查询和校验。
- 异常统一抛 `ClientException`，例如重复集合名、知识库不存在、非法参数。
- 当前用户从 `UserContext.requireUser()` 获取，`created_by/updated_by` 推荐存用户 ID。
- 权限接入现有 RBAC：读接口绑定 `knowledge:read`，写接口绑定 `knowledge:write`，默认先授权给 admin。
- 写代码要写上注释
