# 生产级导购 Agent 分步骤实现方案索引

审阅日期：2026-05-12

本目录把「当前最小可用导购 Agent」升级为「生产级可用 Agent」拆成 9 个阶段。每个阶段都是可评审、可实施、可验收的独立方案，但推荐按顺序执行，因为后续阶段依赖前面建立的运行态、工具协议和模型治理能力。

## 目标定义

生产级可用 Agent 必须满足以下条件：

| 能力 | 生产级要求 |
| --- | --- |
| 自主决策 | LLM 能根据状态和观察选择下一步动作，不只执行固定流程。 |
| 工具协议 | 工具有白名单、入参 Schema、前置条件、超时、错误和审计。 |
| 运行可观测 | 每次运行、每一步、每次工具调用、每次 LLM 调用都能查询和回放。 |
| 状态记忆 | 能保存会话状态、用户偏好、待澄清问题和多轮推荐历史。 |
| 证据约束 | 推荐理由和回答事实能追溯到商品属性或知识库证据。 |
| 安全治理 | 有鉴权、RBAC、限流、幂等、取消、超时、隐私脱敏和审计。 |
| 评测闭环 | 每次策略变更可跑评测集，并定位失败阶段。 |
| 可运营 | 能监控成本、延迟、失败率、工具健康和模型降级。 |

## 推荐实施顺序

```text
01 运行态可观测
  → 02 工具协议
  → 03 LLM 结构化
  → 04 会话记忆
  → 05 召回证据排序
  → 06 前端工作台
  → 07 评测反馈
  → 08 安全运维
  → 09 MCP 服务化
```

其中 01 到 03 是生产级 Agent 的地基。没有它们，后续召回、排序、回答和评测都会缺少可诊断依据。

## 每阶段文档格式

每份文档都包含：

- 目标和边界。
- 当前问题。
- 详细设计。
- 文件和数据结构建议。
- 逐步实施方案。
- 测试与验收。
- 风险和回滚方案。
- 交付清单。

## 最小可上线版本

如果只做第一轮生产化，建议覆盖 01 到 06：

1. 运行态落库和实时步骤 SSE。
2. 工具协议和 Tool Executor。
3. LLM 结构化输出。
4. 会话详情和状态恢复。
5. 证据检索与评分明细。
6. 前端 Agent 时间线。

完成后，系统能回答生产排障最关键的 3 个问题：

1. Agent 为什么走这条路径？
2. 推荐为什么是这个商品？
3. 错误应该修数据、工具、Prompt、模型还是前端展示？
